## 해시 라우팅이 뭐예요?

주소 뒤에 붙는 `#/post/welcome` 같은 부분을 **해시(hash)** 라고 불러요. 해시가 바뀌어도 브라우저는 페이지를 새로 불러오지 않고, 대신 `hashchange` 이벤트만 알려 줍니다. 이 점을 이용하면 정적 호스팅에서도 페이지 이동을 흉내 낼 수 있어요.

> 서버가 없어도 주소로 화면을 나눌 수 있다는 게 핵심이에요.

## 기본 구조

이 블로그도 같은 방식으로 목록과 글 상세를 오가요.

```js
function route() {
  const hash = location.hash || '#/';
  if (hash.startsWith('#/post/')) {
    const slug = hash.slice('#/post/'.length);
    renderPost(slug);
  } else {
    renderList();
  }
}

window.addEventListener('hashchange', route);
route();
```

처음 열 때 한 번, 해시가 바뀔 때마다 한 번씩 `route()`를 실행하는 것이 전부예요.

## 알아 두면 좋은 점

- 뒤로 가기/앞으로 가기가 별도 코드 없이 동작해요.
- 주소를 복사해 공유하면 같은 글이 열려요.
- 없는 slug가 들어올 수 있으니 **찾지 못했을 때의 화면**을 꼭 준비하세요.
- 해시 값은 사용자가 바꿀 수 있으므로, 화면에 출력하기 전에 이스케이프해야 해요.

| 방식 | 장점 | 단점 |
| --- | --- | --- |
| 해시 라우팅 | 정적 호스팅에 바로 사용 | 주소에 `#`이 보임 |
| History API | 깔끔한 주소 | 서버 설정이 필요 |

작은 블로그에는 해시 라우팅만으로도 충분해요.
