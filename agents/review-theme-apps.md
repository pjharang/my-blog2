# Review 서브에이전트 지침: 기존 웹앱의 새 웹앱 규칙 적용 검증

## 역할
Build 서브에이전트가 `apps/2048/`, `apps/pixel-editor/`를 `CLAUDE.md` "웹앱 규칙"의 새 두 규칙에 맞게 고쳤다. 이를 처음 보는 입장에서 검증하고 `review.md`를 작성한다. 지침 원문은 `agents/build-theme-apps.md`.

검증할 규칙
1. 웹앱은 블로그 색상 팔레트를 따른다: 색은 `css/style.css`의 CSS 변수를 참조하고 앱 안에서 색 값을 새로 정하지 않는다(데이터 색 예외는 주석으로 이유가 적혀 있어야 한다).
2. 웹앱에는 화면 안에서 바로 보이는 사용법 안내 문구가 있다.
그리고 기존 기능이 그대로 동작해야 한다.

## 수정 가능 범위
- 생성/덮어쓰기: `C:\Users\Admin\my-blog2\review.md` (기존 내용은 이전 검증이므로 덮어써도 된다. 깃 기록에 남아 있다)
- 수정: `apps\2048\`, `apps\pixel-editor\` 안의 파일 (문제 발견 시에만, 최소 수정)
- 그 외 파일 수정 금지. 커밋 금지.

## 절차
1. 코드 리뷰: `git diff -- apps`와 두 앱의 `style.css`를 읽고 하드코딩된 색(`#hex`, `rgb()`, 색 이름)이 남아 있는지 `grep`으로 찾는다. 남은 색이 모두 "데이터 색 예외"이고 주석이 있는지 확인한다. 블로그 `css/style.css`의 변수 이름을 잘못 쓴 곳(존재하지 않는 변수)이 없는지, `index.html`의 테마 스크립트가 블로그 방식(`data-theme`, localStorage `theme`)과 같은지 확인한다.
2. 브라우저 검증: 빌트인 브라우저 도구(mcp__Claude_Browser__*)로 `http://localhost:8000/apps/2048/index.html`, `.../apps/pixel-editor/index.html`, 그리고 메인 `http://localhost:8000/`를 연다. 서버가 안 떠 있으면 `.claude/launch.json`의 `blog` 설정으로 시작한다. 캐시 때문에 예전 파일이 보일 수 있으니 `?v=숫자`를 붙이거나 `fetch(url,{cache:'reload'})` 후 새로고침한다. 확인 항목:
   - 콘솔 에러 없음, 블로그 CSS를 불러온 뒤에도 레이아웃이 깨지지 않음(앱이 가운데 정렬되고 보드/캔버스 크기가 정상)
   - 라이트/다크 양쪽(블로그의 `data-theme`을 `localStorage.theme`로 바꿔 새로고침, 그리고 `storage` 이벤트로 즉시 반영되는지)에서 글자 대비가 충분하고 배경·패널·버튼 색이 블로그 색상과 같은 계열임
   - 2048: 방향키로 이동·점수·새 게임이 여전히 동작, 오버레이 표시, 사용법 문구 보임
   - 도트 에디터: 점 찍기, 지우개, 채우기, 되돌리기, 격자 토글, 색 선택, PNG 변환 크기(x1/x10/x20, 투명 배경)가 여전히 동작. 사용법 문구가 화면에 보임. 다크로 전환하면 캔버스 격자선 색이 다시 그려져 보임
   - 375px 모바일 폭: 가로 스크롤 없음, 터치 대상 44px 이상
   - 메인 페이지 미니 웹앱 카드의 iframe 미리보기가 두 앱 모두 정상 표시됨
   확인 후 뷰포트, 색상 스킴, 테스트로 바꾼 localStorage 값(`theme`, 앱 저장 키)을 원래대로 복원한다.
3. 문제가 있으면 수정하고 재검증한다.
4. `review.md`에 규칙별·앱별 결과(통과/수정/미확인), 발견한 문제와 수정 내용을 기록한다. 확인하지 못한 항목은 솔직히 미확인으로 적는다.
