# Plan 서브에이전트 지침: 도트 아트 에디터

## 역할
도트(픽셀) 아트 에디터 웹앱의 구현 계획서를 작성한다. 코드는 작성하지 않는다.

## 요구사항 (사용자 요청)
- 16x16 격자에 도트를 찍어서 그림을 그린다
- 색상 팔레트를 제공한다
- 완성한 그림을 PNG 파일로 저장(다운로드)할 수 있다

## 제약 (CLAUDE.md)
- HTML, CSS, JavaScript만 사용. 외부 라이브러리 최소화 (CDN 허용)
- `/apps/pixel-editor/` 폴더 안에서 자체 완결
- 모바일에서도 사용 가능해야 함 (터치로 그리기, 드래그로 연속 칠하기)
- 블로그의 다른 파일은 건드리지 않는다

## 작업 범위
- 먼저 `C:\Users\Admin\my-blog2\apps\2048\` 와 `css/style.css` 를 읽어 기존 앱의 스타일·구조를 파악한다 (읽기만).
- 수정/생성 가능한 파일은 **`C:\Users\Admin\my-blog2\spec.md` 하나뿐**이다. 기존 spec.md(2048 계획)는 덮어써도 된다(깃 기록에 남아 있다). 그 외 파일은 수정 금지.

## spec.md에 포함할 내용
1. 앱 개요 및 기능 목록
   - 그리기 도구(연필, 지우개, 필요하면 채우기), 선택 색상 표시
   - 색상 팔레트(기본 색 목록, 추천 구성과 색 개수), 직접 색 고르기 여부
   - 전체 지우기, 되돌리기(범위 판단), 격자선 표시 토글 여부
   - PNG 저장: 16x16 원본 해상도 vs 확대 저장(예: 배율 선택), 투명 배경 처리, 파일명
   - 작업 중인 그림의 자동 저장(localStorage) 여부
2. 파일 구조 (`/apps/pixel-editor/index.html`, `style.css`, `script.js`)
3. 핵심 로직 설계 (그림 데이터 표현, 캔버스 vs div 격자 비교와 추천, 포인터 이벤트(마우스·터치 통합)로 드래그 그리기, PNG 변환 방법)
4. UI/반응형 설계 (모바일·데스크톱 배치, 칸 크기, 터치 대상 크기, 접근성)
5. 검증 체크리스트 (Review 단계용)
6. Embed 단계: 메인 `index.html`(실제로는 `js/app.js`의 미니 웹앱 섹션)에 추가할 카드 안

선택지가 있는 항목은 추천안을 하나 정하고 이유를 한 줄로 적는다. 간결하게(1~2쪽) 작성한다.
